## 0. 项目背景、用户画像与重设计核心目标

### 0.1 产品定位
**尽欢（ForHappy）** 是社区站点 `https://52dmeme.com` 的 Android 原生客户端。该社区围绕 **LINUX DO** 等泛极客/开发者群体演化而来，核心气质是 **「高频刷梗图 + 高活跃度实时吹水社交 + 职场/公共场合防窥摸鱼 + 轻养成与社区经济」** 的四位一体内容社交空间：
- **内容生产端**：每日高频产出的图片、长图、GIF、短视频、实况图、Markdown 段子与多层加密解密图；
- **社交即时端**：活跃度极高的多群组聊天室与 1 对 1 私信，内嵌高粘性的 **全能红包**、**欢欢猜词屋（实时海龟汤）**、**头衔抽奖** 玩法；
- **防窥刚需端**：大量用户在办公室工位、实验室、地铁通勤场景下使用，极度需要分层且零破绽的防窥与应急伪装能力；
- **轻养成生态**：围绕站内积分「**D 币**」运转的 **鱼鱼谷像素海岛**、**站宠养成与擂台**、**52B 集卡抽卡**、**书房小说与 AI 创作室**、**摸鱼日历/带薪计时器**。

### 0.2 四类真实高频使用场景
1. **通勤 / 碎片时间单手刷梗图**：竖屏大拇指单手滑动，快速预览图/文字帖，一键点赞、贴纸回应或甩一句神评，看到好图一键转到群里斗图，停下看的图自动记为「已看」。
2. **高流速实时水群与群游戏**：数十人同时连发贴纸、引用玩梗、`+1` 复读、抢多平台/猜谜红包、边水群边参与「欢欢猜词屋」猜词或问是非。
3. **工位 / 公共场合防窥摸鱼**：
   - **旁人余光扫视时**：需要整站伪装成 **飞书聊天** 或 **LINUX DO 技术长帖**，并在看起来像正经办公/技术浏览的前提下照常看图、水群；
   - **怕滑出扎眼图片社死时**：需要默认全图模糊，点哪张看哪张，滑走后自动恢复模糊；
   - **他人直接凑到屏幕前时**：需要盲操瞬切全屏 **飞书云文档《Q4 项目复盘》老板键** 死守画面，不能有任何「去点顶栏角落按钮」的低效操作。
4. **日常清体力与休闲消费**：在鱼鱼谷收菜浇水钓鱼串门、给站宠投喂打擂台、看小说并截取片段发群聊、看摸鱼日报与下班倒计时、抽 52B 卡包、在「鞭打」路线图给站长提需求。

### 0.3 本次 UI/UX 重设计的核心诉求
- **彻底摆脱「网页端响应式折叠」感**：网页端依赖悬停弹窗、桌面双栏抽屉（Dock / Split View）、快捷键（`B` 键、双击 `Esc`）和长表单页，生搬到手机竖屏会非常别扭（例如猜词屋分屏、多选筛选栏挤占首屏、独立小窗无法适配）。
- **彻底清除「工程补丁式 UI 堆砌」**：不许再出现「往顶栏/卡片头乱塞小按钮」「在个人页放半屏不能点的死摘要」「把老板键按钮挂在正常界面和伪装界面上」等问题。
- **以 Android 全面屏单手拇指操控为第一性原理**：重写信息架构（IA）、层级深度、手势规范与防窥状态机。

## 1. 当前网站（52dmeme.com）全量功能深度盘点

> 本章盘点网站线上**真实存在并仍在运行**的全部功能、路由与互动规则，同时在 1.15 节明确标注**已下线/已重定向模块**，避免重设计时误设计废弃入口。

### 1.1 账号、权限与认证体系
- **登录方式**：
  1. **LINUX DO OAuth**：登录并同步用户在 L 站的信任等级 `trust_level`（发图/发帖受站点最低信任等级 `minPostTL` 限制）；
  2. **Google / GitHub OAuth**；
  3. **邮箱验证码登录与账号绑定**；
  4. **独立账号密码直连登录**。
- **账户状态**：
  - **游客只读态**：可浏览公开图廊与评论、阅读公共书架小说（书签存本地），不可点赞/回应/发帖/进群聊与私信；
  - **正式成员态**：全功能同步；
  - **受限 / 禁言提示态（`limits`）**：账号存在封禁或限制时，在个人页醒目展示限制类型、截止时间与原因。
- **邀请码与安全**：生成/复制/撤销主站激活邀请码、查看邀请记录与合格邀请奖励；修改密码与三方账号解绑/绑定管理；退出登录。

### 1.2 图廊 / 首页信息流（`/`, `/t/:tag`, `/u/:author`, `/series`, `/s/:series`, `/m/:id`）
- **多维度视图与布局**：
  - 支持 **双列瀑布流**、**单列大卡片流**、**横向画廊模式（`hz`）**（移动端是否保留横向画廊或改良为左右划卡片流由设计师评估）；
  - 支持 **按自然日分组（`byDay`）**：带日期吸顶分栏（如今日、昨日、具体日期），显示当日总帖数与未看数，支持展开「**跳到哪天**」日历快速空降历史某一天；
  - **专题图集（`/series`, `/s/:series`）**：按主题聚合的系列图集索引页与图集内浏览流；
  - **进度记忆与个人锚点（`wallPos` & `anchors`）**：离开图廊再返回（或刷新）自动恢复上次停留帖子位置；用户也可在任意帖子上手动插「**个人锚点**」（或移除），下次从筛选/锚点栏一键跳回继续刷。
- **多维筛选与搜索体系**：
  - **排序**：最新（`new`）/ 热门（`hot`）/ 最早（`old`）；
  - **未看过滤**：**只看未看（`unseen=1`）** 开关；
  - **体裁过滤**：全部 / 只看文字帖 / 不看文字帖；
  - **敏感/NSFW 与剧透内容策略（四档全局联动）**：
    - `hide`（隐藏敏感，默认在图廊/搜索/标签/图集中均不出现）
    - `blur`（模糊显示，出现模糊遮罩并单张点按查看）
    - `show`（直接显示全部敏感内容）
    - `only`（仅看 NSFW 内容，仍保留模糊护眼遮罩）
  - **模糊图点击行为设置（`maskTap`）**：`peek`（点击原地揭开、再点盖回）vs `view`（不原地揭开防当场社死，直接打开独立大图查看器看清）；
  - **发图人多选过滤**、**多标签组合过滤**（点击卡片/详情页标签可直达 `/t/:tag`，点作者直达 `/u/:author`）、**全文关键词搜索**。
- **停留自动标「已看」机制（`SEEN`）**：
  - 在登录态下，信息流卡片进入视口、当前可见图片已加载完毕、且**该卡片不处于全局模糊/NSFW 遮罩状态**时开始计时，**持续停留约 `0.8s–1.0s`**（或直接点开帖子详情页）即自动标记为「已看」；
  - 已看记录本地队列持久化、防抖合并后批量上报 `POST /api/views`，按 `UTC+8` 自然日累计「今日首次看过帖数」，直接联动摸鱼日报的今日任务徽章；
  - **重要视觉原则**：已看状态服务于 `unseen=1` 过滤与摸鱼日报计数，图廊卡片上**不要贴多余的「已看」角标**。

### 1.3 帖子媒体形态与「四层差异化互动」
- **媒体与正文形态**：
  - 单图、多图轮播（`carousel`）/ 九宫格网格；
  - **超长图**（带 `长图` 标记，点击进入竖向全宽可顺滑滚动阅读的长图舞台）；
  - GIF 动图、流媒体视频（支持播放控制与静音/有声切换）、实况照片（`live`）；
  - **局部打码原图切换**：若发帖者上传了「打码版 + 保留原图」，支持在查看时一键切换「看原图 / 看打码版」；
  - **纯文字 / Markdown 富文本长帖**：支持标题、引用、代码块、折叠详情、行内社区贴纸、`[spoiler]` 点击揭开黑幕剧透段；
  - **内嵌多层解密挑战（`puzzle`）**：部分帖子挂载多层看图/文字解谜关卡，用户逐层输入谜底解锁下一层提示，通关可领取 D 币、兑换码或隐藏图文。
- **单帖必须清晰分层的「四层互动」**（设计中切忌把「一句话回应」和「评论区」混为一谈）：
  1. **点赞（`like`）**：红心赞（合显站内赞 + 关联 L 站赞数）；
  2. **表情贴纸回应（`reactions`）**：内置多套社区自制表情包（`ld`、`alu`、`muscle` 等）及通用 Emoji，点击他人已有贴纸胶囊即可 `+1` 或取消；
  3. **一句话助推 / 快捷神评（`quick reply`）**：该社区最具特色的轻量互动层！限 **12 个显示单位以内**（一个 `[pack:name]` 表情算 1 个单位），提供一键预设热梗词（`善`、`甚好`、`欢欢`、`妈妈`、`666`、`太地狱了`、`神！`、`挂！`、`我去~`、`大大大`、`电！！`、`不讲不讲`、`魔了`）及自定义短句；展示在卡片与详情顶部，他人可直接点别人的热评胶囊跟投 `×N` 复读，点击数字可看参与人名单，本人可撤回；
  4. **多级楼中楼评论区（`comments`）**：完整讨论区，支持 `@提及`、引用楼层回复、插入行内贴纸、发送评论配图、**AI 小伙伴评论专属标识**（可互动回复 AI）、删除自己的评论。
- **帖子流转与管理操作**：
  - 加入指定收藏夹（支持多选收藏夹及快捷新建）；
  - **一键转发到已加入的群聊**；
  - 复制帖子链接（`No.1234`）、保存原图/视频到相册、查看搬运源地址（`source_url`）；
  - **作者 / 管理员管理**：编辑已发帖（删图、调整图序、增补新图、对图重新局部打码、改文与标签）、一键切换 NSFW 状态、删除帖子。

### 1.4 发帖 / 投稿工作台（`Compose`）
- **三种发帖体裁**：图片/视频图文帖、纯文字 Markdown 长文帖、以及由剪贴板社交分享链接自动识别生成的快捷分享帖。
- **多文件批量托盘**：
  - 一次选择多个图片、GIF 或视频（单文件上限 20MB，大图端侧自动压缩）；
  - 支持多图发帖策略：**「全部合并为一帖轮播」** vs **「每个文件单独发一帖」**，或对单张图独立开关「单发 / 合并」；
  - 批量连发若中途网络异常部分失败，已发出的自动标记 `已发 No.x`，点击重试仅补发剩余未成功项；支持关闭时「保留草稿」保留已传媒体与文案。
- **上传前局部打码画板（`masker`）**：
  - 支持在图片上框选/涂抹区域，提供 **马赛克 / 高斯模糊 / 纯黑涂抹** 三种打码笔触；
  - 可选是否同时保留原图加密留存（勾上则看帖人点图可看原图，不勾则仅上传脱敏后的成品图，原图绝不上传），打码图发帖自动关联 `#打码` 标签。
- **投稿属性与防打扰设置**：标题（80 字）、Markdown 描述正文（支持快捷格式栏）、推荐预设标签 + 自定义多标签、敏感（NSFW / 慎点）标记、**「关闭本帖 AI 小伙伴评论」开关**、以及挂载多层解密谜题编辑器（`puzzleForm`：问题、提示、答案、层级、奖励）。

### 1.5 实时群聊系统（`/chat`, `/chat/:gid`）
- **频道与准入管理**：
  - 多群组切换（全员默认群 + 主题小群 + 内部审批群），显示实时未读数与 `@我` 提示；
  - 未加入群支持申请入群查看进度；管理员在群内审核入群申请、查看/管理群成员列表、退群通知与 10 天未登录系统自动清理提醒（`chat_idle`）。
- **消息流渲染与富文本能力**：
  - 短时间同人连发自动合并头像与昵称；展示用户佩戴称号、徽章、渐变炫彩昵称与 **专属聊天气泡皮肤**；
  - 每条消息携带唯一楼层号（如 `127165楼`）与发送时间；
  - 富文本解析支持：`[pack:name]` 社区表情包、`:twemoji:`、代码块、折叠详情、`[spoiler]` 黑幕遮罩、`No.1234` 帖子直达预览卡（点开直达帖子详情）、`#标签` 跳转、`@成员` 高亮、外链、图片/GIF/视频网格、以及 **书房小说摘录分享卡片**；
  - **引用回复（`reply_to`）**：PC 右键/悬停、手机端左滑消息快速引用；点击消息内的引用条可滚回原消息并闪光高亮；原消息若被编辑或撤回，引用预览同步实时更新。
- **消息互动与特色操作**：
  - 贴纸回应、一句话助推回应（`boost`）与完整助推记录展开、`+1` 一键跟风复读、引用回复；
  - 编辑自己发送的消息文字、撤回/删除自己消息；
  - **群聊好图一键转图廊帖子（`to-post`）**：在群里看到好图，可直接打包转投稿到主站图廊。
- **历史搜索、上下文回跳与新消息体验**：
  - 群消息全文关键词搜索与按发言人筛选；
  - 从通知（`@我` / 群聊回复 / 红包结果）、搜索结果或引用点击跳入历史消息时，支持 **上下文定格加载（`around`）+ 高亮目标楼层 + 一键「回到最新消息」浮标**；
  - 支持配置「**新消息自动滚动策略**」（仅在底部时跟随 / 总是滚到最新 / 不自动滚仅出 `N 条新消息` 提示条）以及「**离开期间新增 X 条未读消息**」提醒横条。

### 1.6 群内核心社交游戏：全能红包、欢欢猜词屋、头衔抽奖
1. **全能红包系统（`redpacket.js`）**：
   - **四大渠道**：站内原生 **D 币红包**（`native` / `coin52`）、**HB 红包**（`hb`）、**LINUX DO Credit 红包**（`credit`）、**Fish 红包**（`fish`）；（注：外部平台支持状态快照查询、定时开奖自动同步与领取跳转/授权）；
   - **多种派发机制**：普通定额/均分、拼手气、指定人专属红包、限时定时抽奖开奖（带精准倒计时与开奖状态）、口令兑奖、文本 / CDK 奖品；
   - **四种开包门槛玩法**：
     - ① **直接开（`open`）**；
     - ② **复读口令开（`phrase`）**：按规定口令在群里复读拆开；
     - ③ **文字解谜小游戏开（`cipher`）**：内置 6 种规则谜题（双轨密码、回廊字阵、两步电台、倒放咒语、错位电波、弹幕拼字）；
     - ④ **局部清晰猜图开（`image`）**：发包人选择站内图片并勾选九宫格中的若干清晰格，端侧合成不可靠改样式还原的真马赛克线索图，猜中图梗拆开；
   - **辅助视图**：红包封面自定义、拆包结果弹层（含未抢到的趣味小猫空手插画）、领取明细表、**群红包手气榜（`packetLuckRanks`）**、群历史红包归档列表。
2. **欢欢猜词屋（`guess-room.js`）** —— 网页端为右侧分屏，**手机端如何顺畅承载是本次重设计的重点难题之一**：
   - 与当前群聊绑定的实时海龟汤 / 猜词互动区；
   - **双发言模式**：`猜答案`（提交猜测，系统按语义相关度打分并标注命中字）vs `问是非`（如「第一个字是水吗」「答案有三个字吗」，由规则引擎或 AI 实时判定「是 / 否 / 无法判断 / 不是问题」）；
   - **实时情报看板**：高相关答案榜、已确认「是」列表、已确认「否」列表、可折叠展开的「无法判断 / 不是问题」清单；
   - **轮次工具链**：本轮截止倒计时、当前已公开线索、一键发送 `@欢欢 线索` 要提示、出题人特权（查看答案密匣、手动追加最多 60 条公开线索）、参与人投票流局、猜中者打赏 D 币（`guess-tip`）；
   - **排队与榜单**：**等候队列（`guess-queue`）**（支持发起无奖娱乐局或 D 币 / LDC 悬赏局，上一局结束 1 分钟内自动发下一局）、历史轮次复盘、**战绩榜**（`今日` / `开站以来` × `猜中榜` / `胜率榜`）。
3. **头衔抽奖（`title-raffle`）**：群内由系统/管理员发起的限定头衔抽奖系统卡片与一键报名参与。

## 2. Android 客户端（ForHappy）必备能力与「原生 vs 混合」承载边界

Android 客户端不仅是网站套壳，它还肩负着**抗网络干扰直连、应用自主更新、系统级防窥与移动端物理交互优化**四项核心职责。重设计时必须明确划分「哪些必须 100% 原生 UI 精心打造」「哪些客户端独有面板需要优雅入口」「哪些低频重画布子应用交由加速内嵌容器承载」。

### 2.1 客户端独有的底层与系统级能力（必须在 UI/IA 中给出合理安置）

1. **内置 Rust 抗干扰网络加速内核（DoH + TLS 1.3 ECH + Edge IP 优选 + HTTP/2）**
   - 客户端内嵌本地 Rust 网络代理引擎，绕过异常 DNS 与 SNI 阻断，并自动优选 Cloudflare 边缘节点 IP。
   - **UI 呈现约束**：
     - **正常态主界面**：保持极简无感。连接健康时不要用显眼绿色横幅或悬浮药丸不断刷存在感；仅在未就绪、重连中或测速异常时给出一句温和可点击的状态提示或跳转到网络诊断页；
     - **伪装模式 / 老板键下**：**绝对禁止**露出任何 `ECH`、`Edge IP`、`ms` 延迟数字或任何暴露代理身份的文字与图标；
     - **设置内的独立「网络加速与内核诊断」页**：必须完整保留现有能力——展示引擎端口与阶段、当前优选 Edge IP 与 RTT 延迟、ECH 协商状态与钥匙数、节点来源、开关 ECH、IPv6 策略切换（自动 / IPv4 优先 / IPv6 优先 / 禁用）、**自定义优选 IP 节点增删开关**、一键重测优选、查看最近内核运行日志。
2. **应用内多镜像竞速自动更新器（`AppUpdateManager`）**
   - 直接请求 GitHub Releases 检测新版本，并内置 30 个公益加速镜像池（支持定期同步更新列表）、分层洗牌 + 4 路并发首字节竞速 + 下载速度低于 `40 KB/s` 自动断链切源并用 HTTP `Range 206` 断点续传 + **支持用户配置自定义 GitHub 加速前缀**。
   - **UI 呈现需求**：启动静默检测有新版本时提供不打断当前看图/水群的温和更新提醒；进入更新页/弹窗可见完整 Release Notes、实时下载进度条、允许安装未知应用引导与一键覆盖安装；不可把「更新进度、自定义加速源输入框、Release Notes 预览」长期铺死在「我的」主屏占用大量滑屏高度，建议收口到次级设置页或简洁版本行 + 弹层。
3. **系统级隐私保护与硬件物理能力联动**
   - **桌面启动器图标与名称伪装（`Activity-alias`）**：支持一键把手机桌面的 App 图标和名称切换为 **「尽欢」** / **「飞书文档」** / **「协作文档」**。
   - **防截屏与多任务后台缩略图掩护（`FLAG_SECURE`）**：一键开关，防止他人划开手机多任务切换视图时从缩略图看到真实内容。
   - **多维盲操传感器 / 物理键触发器**（详见第 3 章防窥规范）：
     - 450ms 内无弹窗连滑两次系统返回；
     - 双击物理音量上键 / 音量下键（可分别绑定触发老板键或全图模糊，互不冲突）；
     - 加速度计感应「手机屏幕朝下扣放桌面」自动瞬间切入云文档老板键；
     - 「轻晃手机」触发全图模糊开关；
     - 切后台 / 息屏锁屏归来自动开启全图模糊，或直接定格为云文档老板键。
4. **Android 系统协同体验**
   - **App Links 深度链接唤醒**：拦截并承接浏览器中点开的 `52dmeme.com` / `cc.52dmeme.com` 帖子、标签、群聊、作者链接，直接进入客户端对应页面；
   - **系统分享接收与向外分享**：从相册/其他 App 点击「系统分享 → 尽欢」可直入发图工作台或发往群聊；在站内支持原图/GIF/视频一键保存到系统相册；
   - **本地持久化与断网/弱网韧性**：Room 本地缓存用户分段的群聊历史（修复过分段中间断层问题，拉取上下衔接自然）、本地记录 `1s` 已看待同步队列、表情包资源失败防 HTML 污染兜底与磁盘缓存管理、发帖本地草稿留存。

### 2.2 「原生 UI」与「无壳加速 WebView 容器」的合理边界划分

> 客户端具备 `ShelllessWebScreen`（与原生共享 `PersistentCookieJar` 登录态 + 本地静态资源离线缓存 `WebAssetCache` 的无浏览器地址栏加速 WebView），切忌因为懒而全套网页，也不要因为追求全原生而把低频重画布游戏硬写成拙劣的 Compose 表单。

| 优先级与实现形态 | 涵盖模块 | 重设计定位与界面要求 |

## 3. 移动端核心使用场景与历史踩坑红线（设计铁律）

以下每一条均来自前序版本中**用户真实重度吐槽与反复打磨后的明确结论**。新方案如违反其中任何一条，均视为设计不合格。

### 红线 1：彻底理清「界面伪装 / 全图模糊 / 老板键」三层防窥分工，严禁叠床架屋
这三者不是同一功能，各自服务于三种完全不同的职场风险等级：

1. **第一层：界面伪装（飞书 IM / LINUX DO 帖子）—— 防「路人余光扫视」且「还要继续用」**
   - **使用意图**：工位背后偶尔有人走过，余光瞟一眼以为你在用飞书看工作群或逛 LINUX DO 查技术资料，而用户自己**依然要流畅地看图、点表情/一句话回应、看评论、在真群聊和私信里水群**。
   - **刚性要求**：
     - 切入伪装后，**必须彻底消灭原版娱乐元素**：禁止再露出原版「图廊 / 鱼鱼谷 / 百宝箱 / 尽欢松绿品牌色 / 摸鱼赚了多少钱 / ECH 与 ms 技术网络标」。
     - **飞书伪装的底栏保持极简真实**（如只有「消息」和「设置/我的」，或贴近真飞书的纯粹信息流结构），**绝不能为了凑老板键而在飞书底栏塞一个假「云文档 Tab」挤占空间或露馅**。
     - **飞书视觉真实度**：图廊每日更新伪装成 12 个轮换工作群，帖子映射到约 40 位中文真名同事；**必须包含与真实群聊、真实私信（可做「工作组 / 个人消息」自然分类或混排）一致的搜索与气泡交互**，图片展示像飞书工作群文件/截图预览（非尽欢圆角卡片），支持点击消息进类似飞书回复串（Thread）的帖子详情。
     - **LINUX DO 视觉真实度**：模拟 Discourse 论坛长帖盖楼流、分类标签、右下角/右侧可点按跳转到指定楼层的进度条、以及顶部/侧边隐蔽拉出的论坛聊天频道抽屉。

2. **第二层：全图模糊（防突现）—— 防「刷着刷着突然滑出大尺度/奇葩图社死」**
   - **使用意图**：哪怕已经伪装成飞书或正常刷流，手机竖屏卡片大图占满屏幕，滑出 NSFW 或社死图极其危险。
   - **移动端改良（告别网页按 `B` 键思路）**：
     - 进入伪装模式时可自动联动开启「全图模糊」；退出伪装自动还原进入前的状态；
     - **点开看清的图片在滑出当前视口（或离开页面）后自动恢复模糊**，省去用户再手动点第二下遮上的麻烦；
     - 支持切后台/息屏归来自动重新进入模糊保护。

3. **第三层：老板键（飞书云文档《2026 Q4 项目复盘与规划》）—— 防「有人直接走到身边盯屏幕」或「手机扣放桌面」**
   - **使用意图**：危险逼近需要**零脑力反应、1 秒死守掩护**的静态文档页面（必须带逼真的知识库面包屑、协作者头像、目录导航、正文数据表格、待办勾选列表，允许假装上下滑动看文档）。
   - **刚性防露馅铁律**：**云文档页面上绝对禁止出现「恢复正常视图」「退出老板键」「返回尽欢」等任何文字按钮或浮标！** 旁边的人扫一眼看到这种按钮会当场暴露。退出老板键只能通过**隐蔽手势**或已配置的盲操触发器（例如文档页再次触发同一快捷手势，或长按某个看似无害的文档标题/固定隐蔽点）。

### 红线 2：主界面「零废柴按钮」原则 —— 严禁在正常屏显区域塞老板键 / 一键糊图按钮
- **反面教训**：前序版本曾在「正常模式顶栏、我的页面设置卡片右上角」摆放老板键按钮或糊图小图标——用户在真正遇到突发情况时，根本不可能去冷静瞄准屏幕右上角一个 `24dp` 的按钮；平时放在主界面反而增加视觉噪音、误触率和露馅概率。
- **正确做法**：**正常界面和伪装界面的一级视觉区不要常驻任何「老板键触发按钮」**。所有老板键与模糊快捷触发器（连滑两次系统返回、双击音量上/下键、翻转手机屏幕朝下扣桌、轻晃手机、切后台/锁屏自动挂起）统一收纳到「防窥与摸鱼设置」中供用户按肌肉记忆勾选组合。

### 红线 3：停留 `1s` 自动标已看必须「静默无痕」，严禁在卡片上贴「已看」角标
- 信息流卡片（无论是双列瀑布流、单列、还是伪装模式消息）应当尽量干净通透，把空间留给图片、标题、表情贴纸和神评胶囊。
- 「已看」追踪是纯粹在背后运行的状态机，不要在每张图右上角挂一个刺眼的「已看 / ✓」标签破坏观感。

### 红线 4：高信噪比，严禁堆砌「占半屏却无法闭环操作」的鸡肋模块
- **反面教训**：旧版曾把整个通知列表的「静态 4 条纯文字预览大卡片」硬塞进「我的」页面里占掉大半屏，结果每条点不动、看不了公告全文、也跳不到对应帖子和群聊；还曾把所有应用更新/自定义镜像输入框/Rust 全量开关全摊在「我的」首页无限下拉。
- **正确做法**：
  - 核心摘要入口必须克制紧凑（例如顶栏带实时红点数字的铃铛图标 + 个人页一行紧凑带角标入口），点开即进入完整的 **全功能互动抽屉/独立页**（含分类 Tab、单条/一键全部已读、跳转原帖/群聊、完整公告弹窗与 16 项偏好开关）。
  - 个人中心与设置中心合理分层：**高频日常操作与资产（我的内容 6 栏、收藏夹、D 币、摸鱼状态）** 放在前排直观可读；**低频工程配置（网络内核日志、自定义节点、镜像加速地址、图标伪装配置）** 干净折叠到「设置」二级页面，绝不把首页变成程序员控制台。

### 红线 5：全面屏单手大拇指优先 + 系统手势防冲突 + 极致内容视口
- **视口最大化**：在图廊、详情大图与群聊消息流页面，顶部栏必须极致克制紧凑，切勿叠放多层标题栏 + 状态栏 + 搜索条 + 二级 Tab，把宝贵的屏幕高度还给梗图和聊天消息。
- **单手大拇指热区**：高频切页、快速返回、发送与展开工具集中在屏幕下半区（拇指自然半径内）。
- **必须避让 Android 全面屏边缘手势**：
  - 现代 Android 手机屏幕左右两侧边缘（约 `16–24dp` 区域）是**系统全局侧滑返回手势热区**；
  - 凡是页面内的横向操作（如手机端聊天「**左滑消息引用回复**」、图片轮播滑动、标签横滑），**起点判断必须避开左右屏幕边缘，或与系统边缘返回共存冲突消解**，防止想引用消息却误退出了整个聊天页。

### 红线 6：高流速群聊与多任务切换的「零跳动视口锚定」工程体验
这是移动端即时通讯成败的关键细节，新交互设计必须明确要求并设计到位：
1. **软键盘弹起锚定**：当用户停留在群聊底部最新消息时，点击输入框拉起系统软键盘，消息列表底部必须随键盘顺滑上移，**绝不能遮挡最新几条消息**；若用户正上翻看历史消息时拉起键盘，也不要强行把他拽回底部。
2. **向上分页加载防跳动**：上拉加载更早分段历史消息时，当前正在看的消息必须像素级停留在原地，绝不能突然跳回页顶或跳乱楼层。
3. **上下文回跳清晰可逆**：从搜索结果、通知或引用条空降历史楼层时，必须有清晰的定位高亮与「回到底部最新消息」一键悬浮胶囊。
4. **群聊 ↔ 猜词屋切换不丢进度**：竖屏手机下在群聊流与「欢欢猜词屋」之间切换时，各自保留滚动位置、当前已输入的半截草稿（猜测 vs 问是非模式）与实时状态更新提示（如猜词出结果或新轮开始时温和提醒，不粗暴打断打字）。
5. **行内社区表情包兼容排版**：消息文本混排 `[pack:name]` 动态/静态表情包时，行高自然、不截断左右字符、弱网加载失败有稳定尺寸占位符。
